# gpuicn v0.12.1

Long lists stay fast as they grow. Paging a Commit graph through a large
history and opening every folder of a large Tree no longer rebuild the whole
component each time. There are no breaking changes. The runtime pins are
unchanged: GPUI Kit 0.9.1 on `gpui-pre` 0.3.12, and gpui-icons 0.7.0.

## Why

Bonsai pages through a 100,000-commit history 500 commits at a time. With only
`replace_rows`, each page copied and re-indexed every row already loaded, so
the 200th page cost hundreds of milliseconds on the main thread. A Tree of
10,000 changed files opened each of its folders with `set_expanded`, which
rebuilds the visible rows on every call: 150 ms before the first paint.

## Added

- **`VirtualListState::append_items`** adds items after the last one. It is
  O(appended), leaves selection, focus and the scroll position alone, and
  rejects a duplicate ID without changing anything.
- **`CommitGraphState::append_rows`** does the same for a page of older
  history, widening the lane column when the new rows need it.
- **`TreeState::expand_folders`** expands many loaded folders with one
  rebuild, such as every new folder after `replace_nodes`. Unknown IDs,
  leaves and unloaded folders are skipped.

## Measured

On Bonsai's 100,000-commit test repository, the slowest history page fell
from 234 ms to 17 ms, and the Changes tree of 10,000 files opens in 14 ms
instead of 150 ms.
