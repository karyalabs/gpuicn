# gpuicn v0.13.3

Long lists append without stalling. There are no API changes. The runtime
pins are unchanged: GPUI Kit 0.10.0 on `gpui-pre` 0.3.12, and gpui-icons
0.7.0.

## Why

Bonsai pages a 100,000-commit history into a Commit Graph 500 rows at a
time, with a budget of 8 ms of main-thread work per page so scrolling stays
at 120 fps. Most pages took about 1 ms, but a few took 12 to 16 ms: the ones
where the row `Vec` doubled and copied every row, or the ID `HashMap` passed
its load factor and rehashed every ID. Those moments grow with the list, so
the longest history stalled the most.

## Fixed

- **Virtual List:** rows are stored in chunks of 4,096, and the ID index is a
  map per chunk, allocated at full size. Appending never moves or rehashes
  rows that are already there. Lookups by ID check one map per chunk, which
  is still a handful of hash lookups at 100,000 rows.
- **Commit Graph:** its rows use the same chunked storage.
- **Both:** replacing a list of more than 4,096 rows frees the old rows on a
  background thread. Freeing 100,000 rows took longer than a frame.

Measured with Bonsai's 100,000-commit benchmark, the slowest page's
main-thread work went from 8.8 ms to 3.5 to 5.2 ms. Replacing the fully
loaded history went from 27 ms to 9 ms.
