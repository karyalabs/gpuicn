# gpuicn v0.10.0

A breaking release that gives every component handler one of three shapes
(#168). The runtime pins are unchanged: GPUI Kit 0.9.0 on `gpui-pre` 0.3.11
and gpui-icons 0.6.0.

## Changed (breaking)

A handler that reports one value now takes it by reference, as
`Fn(&T, &mut Window, &mut App)`, and value changes no longer pass the click
that caused them. That is the shape `cx.listener` returns, so a view can hand
any of these a listener directly:

```rust
Switch::new("compact")
    .checked(self.compact)
    .on_change(cx.listener(|this, compact: &bool, _, cx| {
        this.compact = *compact;
        cx.notify();
    }))
```

| Component | 0.9 | 0.10 |
|---|---|---|
| `Checkbox`, `Switch`, `Toggle` `on_change` | `(bool, &ClickEvent, &mut Window, &mut App)` | `(&bool, &mut Window, &mut App)` |
| `Tabs`, `RadioGroup` `on_change` | `(SharedString, ..)` | `(&SharedString, ..)` |
| `CheckboxGroup`, `ToggleGroup` `on_change` | `(Vec<SharedString>, ..)` | `(&[SharedString], ..)` |
| `Calendar` `on_select` | `(CalendarDate, ..)` | `(&CalendarDate, ..)` |
| `MessageList` `on_select` | `(Option<usize>, ..)` | `(&Option<usize>, ..)` |

Unchanged, because they already had the shape: `Popover::on_open_change`,
`ShowMore` / `Collapsible` / `Embed` `on_toggle`, `Resizable::on_resize`,
`SidebarLayout::on_change`, `Sortable::on_reorder`, the Markdown link and
image handlers and `Message::on_reaction`. Click handlers keep
`&ClickEvent`. Handlers that report more than one value, such as
`Sortable::on_reorder_group(from, to, ..)`, still take them in order.

### Migrating

- Drop the event argument from `Checkbox`, `Switch` and `Toggle` closures and
  dereference the value: `|checked, _, _, cx| .. = checked` becomes
  `|checked, _, cx| .. = *checked`.
- Where a closure stored the owned value, clone it: `next.clone()` for a
  `&SharedString`, `next.to_vec()` for a `&[SharedString]`.
- `*date` and `*index` for `Calendar` and `MessageList`.

## Added

- `docs/design.md` documents the handler shapes, and the registry lint fails
  on a one-value handler that takes its value by value.
